Workflow anatomy

A workflow is one WorkflowSchema. This page lists every object and field you can set. For how these objects are checked before a run, see Build checks.

Note

Each workflow is one file, and the workflow’s schema_id matches the filename. In the app you never touch files directly; you design on the canvas and it writes them for you.

Top-level objects

Section titled “Top-level objects”
ObjectRequired keysNotes
WorkflowSchemaschema_id, name, description, nodes, edges, configThe top-level container.
NodeDefinitionnode_id, node_type, label, config, positiongroup_config is required only when node_type is agent_group.
EdgeDefinitionedge_id, edge_type, source_node_id, target_node_idloop_rounds appears only on loop-closing edges.
WorkflowConfigtotal_timeout, logging_level, max_loop_rounds, max_iterations, iteration_sleep, save_log, on_node_failureRun-level configuration.

node_type is one of agent, agent_group, or tool. edge_type is one of data_flow, tool_call, or synchronization.

Caution

These removed fields now fail the check, so do not reintroduce them: NodeConfig.termination_conditions, completion_contract.criteria, completion_contract.missing_input_policy.

WorkflowConfig

Section titled “WorkflowConfig”

Run-level settings for the whole workflow.

FieldMeaning
total_timeoutMaximum wall-clock seconds for the whole run.
logging_levelEvent verbosity: none, errors, critical_info, info, all (all includes full model payloads).
max_loop_roundsGlobal hard ceiling for any loop count set on a connection.
max_iterationsDefault loop budget for nodes with agent_loop_default: true.
iteration_sleepSeconds to pause between loop iterations.
save_logWhen true, the run writes a log file.
on_node_failurecontinue (record and keep going; run ends partial) or fail_fast (halt on the first node that does not complete).

NodeDefinition.config (NodeConfig)

Section titled “NodeDefinition.config (NodeConfig)”

Set per node. Tool nodes carry the same object, but only tools is meaningful for them.

FieldMeaning
providerModel provider: openrouter, openai, anthropic, google, ollama, vllm, llama_cpp.
model_idModel identifier for that provider (empty on tool nodes).
temperatureSampling temperature.
max_tokensOutput token cap; null means the provider default or maximum.
completion_check_max_tokensToken cap for the success-check call.
response_formatOptional structured-output schema (null for free text).
instructionThe procedure: an ordered list of imperative bullets sent as one user message.
retriesRetry count on a failed model call.
retry_waiting_timeSeconds between retries.
completion_contractWhen the node may succeed. See Success rules.
token_budgetBudget for assembled context; upstream data is trimmed largest-first to fit.
scope_windowFew-shot and history window size.
toolsTools this node exposes. On tool nodes only; agent nodes keep this [] and gain tool access through a tool_call edge.
tool_strictEnforce strict tool-argument schemas.
tool_choiceauto, required, or none.
parallel_tool_callsAllow multiple tool calls in one turn.
call_budgetMaximum tool calls the node may make.
rate_limit_per_minutePer-node tool-call rate limit.
few_shot_examplesOptional {role, content} examples (windowed).
agent_loop_defaulttrue takes a single-node loop budget from WorkflowConfig.max_iterations; false takes the budget from a self-loop edge’s loop_rounds.
read_upstream_stateRead state exposed by upstream nodes.
expose_downstream_stateExpose this node’s state and evidence to downstream nodes.
read_orchestration_stateRead run-level state.

NodeDefinition.group_config (AgentGroupConfig)

Section titled “NodeDefinition.group_config (AgentGroupConfig)”

Required only on agent_group nodes. The upstream planner decides the exact number and structure of sub-agents within these bounds.

FieldMeaning
max_parallel_agentsMaximum sub-agents running at once.
min_agents / max_agentsBounds on group size.
group_structureparallel, sequential, pyramid, or default (planner decides).
shared_contextShared memory available to every sub-agent.
sub_agent_read_group_stateWhether sub-agents read the group’s shared state.
sub_agent_instructionsInstructions applied to each sub-agent.

EdgeDefinition

Section titled “EdgeDefinition”
FieldMeaning
edge_idUnique connection identifier.
edge_typedata_flow, tool_call, or synchronization.
source_node_id / target_node_idEndpoints; both must exist.
loop_roundsIteration budget on a loop-closing connection (null otherwise), capped by max_loop_rounds.

NodeDefinition.position

Section titled “NodeDefinition.position”

position.x and position.y are canvas coordinates. There is no auto-layout; the canvas shows exactly what you set. See Nodes, connections, and loops for layout rules.
