The **Settings** tab manages two things: the **model providers** your agents
call, and the **data sources** your tools fetch from. A workflow runs only when
both are ready.

<Aside type="note">
Keys are held in the running app for your session, so your agents and tools can use them while a workflow runs. They are never saved into a workflow file and never shared between users.
</Aside>

## Model providers

Every agent uses a provider and a model, and the provider has to be set up here.

### Cloud providers

**OpenRouter, OpenAI, Anthropic, and Google** each have a row where you enter an
API key, **Test** it against the provider, and **Save** it. The row shows whether
that provider is set up.

All the [example workflows](/guides/patterns/) default to **OpenRouter**, so
adding one OpenRouter key is enough to run them.

### Local model servers

**Ollama, vLLM, and llama.cpp** each take a web address instead of a key. Enter
the address (for example `http://localhost:11434/v1` for Ollama), **Test** the
connection, and **Save**.

### Choosing a model for each agent

The provider and model are set on each agent, not once for the whole workflow. In
an agent's panel, pick the provider, then choose a model from the list it loads
(you can also type a model name). This is how one workflow can run a cheap model
for gathering data and a stronger model for the final write-up.

## Data sources

Tools fetch from outside sources. There are two kinds.

### Public sources

Sources that need no key, such as the **OKX** exchange, the **ECB** for macro
data, and **Guardian**, **Lemmy**, and **Mastodon** for news and social posts.
The **Public Data Tools** section lists them by category, each with a toggle. Turn
on the ones your workflows use.

### Sources that need a key

Some sources require a key. The **Additional Tool APIs** section lets you add a
source's key (and an optional web address) so those tools can reach it, and remove
it later.

## Matching credentials to a workflow

Before running a workflow, check what it touches:

- the provider and model on each agent, so you can set up that provider above;
- the data sources its tools use, so you can turn those on.

Each entry in the [example gallery](/guides/patterns/) lists the data sources its
workflow uses, so you can get ready before you run.
