Every workflow in the [example gallery](/guides/patterns/) is a downloadable file
you can run as is. The fastest way is to import it in the hosted app. If you run
your own copy of Price Monitor Agent, you can also drop the file in and reload.

<Tabs>
<TabItem label="Hosted app (Import)">

Load the file onto the canvas, review it, and save it. This is the same path you
use to edit any workflow.

<Steps>

1. **Download** the example you want, for example
   [`sequential_analysis.yaml`](/examples/sequential_analysis.yaml).

2. In the app's **Canvas** tab, click **Import YAML** on the Schemas panel and
   choose the downloaded file.

3. The workflow loads onto the canvas exactly as saved, with the same nodes,
   connections, setup, and layout. Click any node to inspect it in the right-hand
   panel.

4. Click **Save**. The app checks the workflow when you save it and adds it to
   your schema list. If something is wrong, the problem appears in the panel
   banner and nothing is saved.

5. Select the workflow and click **Run**.

</Steps>

<Aside type="note">
Import keeps the file's own name. If a workflow with that name already exists in your list, saving updates it; otherwise saving creates a new one. To keep both, rename the workflow before saving.
</Aside>

**Export YAML** does the reverse: it downloads the current canvas as a file you
can share, back up, or run in your own copy.

</TabItem>
<TabItem label="Your own copy">

If you run your own copy of Price Monitor Agent, workflows are loaded from a
folder on disk.

<Steps>

1. **Download** an example, or **Export YAML** one you built in the app.

2. Save it into your copy's workflows folder, keeping the filename.

3. **Check it first** (recommended). See [Build checks](/reference/validation/)
   for what is verified and how to run the check yourself.

4. **Reload** so the workflow appears in the Schemas panel, then select it and
   **Run**.

</Steps>

<Aside type="caution">
The hosted app does not accept files dropped onto disk, so use **Import YAML** there. The drop-in route is for a copy you run yourself.
</Aside>

</TabItem>
</Tabs>

## Before you run: credentials

An example runs only if its tools can reach their data and its agents can reach
their model.

- **Model provider.** Every agent uses a provider and model. Add that provider's
  key on the **Settings** tab, or switch the agent to a provider you already
  have. All the examples default to OpenRouter.
- **Data sources.** Public sources like OKX (exchange), the ECB (macro), and
  Guardian, Lemmy, and Mastodon (news and social) need no key. If a workflow
  points at a source that needs a key, add it under **Settings**.

See [Set up your keys and data sources](/guides/configure-providers/) for the
details, and each entry in the [example gallery](/guides/patterns/) for the data
sources a given workflow uses.
