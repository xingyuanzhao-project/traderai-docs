Tools are the capabilities agents call while they run. They are named in a
workflow, take arguments from the calling agent's instructions, and return typed,
evidence-bearing output.

An agent gains a tool by being connected to a tool node whose `config.tools` lists
it, through a `tool_call` edge. Each tool's credentials come from your Settings at
run time. See [Set up your keys and data sources](/guides/configure-providers/).

## Fetch data

Acquire real market, macro, news, and social evidence.

| Tool | Purpose |
|---|---|
| `fetch_exchange_data` | Market data: OHLCV candles, tickers, order books, trades, funding rates. |
| `fetch_macro_data` | Macro and alternative data: policy rates and economic indicators. |
| `fetch_news_data` | News and filings: headlines and articles. |
| `fetch_social_media_data` | Social posts, threads, and hashtag timelines. |

The examples call these with a `source_id`, a `source_type`, and query arguments,
for instance:

```text
fetch_exchange_data  source_id='okx',  source_type='ticker',         symbol='BTC-USDT', limit=1
fetch_macro_data     source_id='ecb',  source_type='interest_rates', indicator='MRR_FR', limit=1
fetch_news_data      source_id='guardian', source_type='search',     query='Bitcoin', limit=5
fetch_social_media_data source_id='mastodon', source_type='hashtag', query='Bitcoin', limit=5
```

A tool's returned `data_type` is the source id and source type joined with an
underscore (for example `okx_ticker`), which is what success rules match against.
See [Success rules](/reference/completion-contracts/#the-data_type-convention).

## Data analysis

Compute over fetched market data.

| Tool | Purpose |
|---|---|
| `technical_analysis` | Technical indicators (RSI, MACD, Bollinger Bands, ATR, VWAP, moving averages, and more). |
| `quantitative_analysis` | Statistical metrics (alpha, beta, Sharpe, drawdown, correlation, and more). |
| `signal_analysis` | Higher-level signal detection: patterns, threshold crossings, supports, divergence. |
| `diagnostic_analysis` | Diagnostic checks over series. |
| `detect_regime` | Regime detection. |
| `estimate_parameters` | Parameter estimation. |
| `simulate_process` | Process simulation. |
| `run_monte_carlo` | Monte Carlo simulation. |

## Text analysis

Turn large amounts of text into structured, scored signal.

| Tool | Purpose |
|---|---|
| `chunk_text` | Chunk, window, deduplicate, and normalize large text. |
| `semantic_search` | Retrieve over stored data or documents. |
| `extract_entities` | Named-entity and relationship extraction (tickers, companies, people, dates). |
| `classify_text` | Classify text into categories. |
| `score_text` | Score sentiment, relevance, or credibility, per document and per entity. |
| `summarize_text` | Single-doc, multi-doc, and delta summarization. |
| `cross_modal_alignment` | Anchor text claims to fetched structured data. |

## Output

Send results outside the workflow.

| Tool | Purpose |
|---|---|
| `send_webhook` | Post to a webhook. |
| `send_email` | Send an email alert. |
| `send_telegram` | Send a Telegram message. |
| `write_output` | Structured export or append to a dataset. |

<Aside type="tip">
Split fetch and analysis onto separate tool nodes when different agents call them, for example a fetch node for the collector and a text-analysis node for the analyst, as in [News and Social Pulse](/guides/patterns/#news-and-social-pulse).
</Aside>
