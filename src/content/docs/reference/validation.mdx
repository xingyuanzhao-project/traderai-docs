Every schema is validated before it can run. Source of truth:
`backend/schema/validation.py` (`SchemaValidator`). Validation happens in two
places automatically — when the app loads `schemas/` at startup, and when you
save from the editor — and you can run it yourself locally.

## What the validator enforces

**Structural integrity**

- Every `node_id` is unique; every edge endpoint exists.
- `node_type` ∈ {`agent`, `agent_group`, `tool`}; `edge_type` ∈ {`data_flow`,
  `tool_call`, `synchronization`}.
- `agent_group` nodes carry `group_config`.

**Edge semantics**

- `data_flow` consumers are `agent`/`agent_group` (tools receive input only
  through calls).
- Tools are authorized only through `tool_call` edges; agents with tool access
  keep `config.tools: []`.

**Loops**

- A node with `agent_loop_default: false` that loops must have a self-loop
  `data_flow` edge carrying `loop_rounds`.
- `loop_rounds` ≤ `config.max_loop_rounds`.
- The dependency graph must be **reducible** (single-entry loops).

**Completion contracts**

- Every requirement's `tool_names` is **reachable** — directly via a `tool_call`
  edge, or indirectly via `data_flow` with `expose_downstream_state` upstream and
  `read_upstream_state` downstream.

<Aside type="caution">
Three legacy fields now **hard-fail** validation: `NodeConfig.termination_conditions`, `completion_contract.criteria`, and `completion_contract.missing_input_policy`. Remove them from any old schema before running.
</Aside>

## Validate locally

Two levels, matching the project's own test harness.

**Level 1 — structural (offline, free, instant).** Parse and validate without
calling any model or data API. This is what confirms a schema is well-formed
before you ship it. In the running app, saving a schema runs exactly these
checks server-side and rejects an invalid schema with the failing reason.

**Level 2 — live end-to-end (costs tokens and hits data APIs).** Execute the
schema against the running app with real provider keys and confirm each node
reaches `completed` with the required evidence. Reserve this for schemas you are
about to publish or run on a schedule.

<Aside type="note">
The seven bundled [examples](/guides/patterns/) all pass Level 1 structural validation. Validate your own schema at Level 1 before every commit, and at Level 2 before you rely on it.
</Aside>

## Pre-ship checklist

Before you publish or schedule a schema:

1. It validates at Level 1 with no errors.
2. Every agent node has `mode: explicit` with at least one evidence-backed
   requirement (planners/critics may use `evidence: null`).
3. Every `tool_names` entry in a contract is reachable from that node.
4. `label`s are tight functionary roles; procedures live in `instruction`.
5. Loop budgets (`loop_rounds`, `max_iterations`) are set deliberately, within
   `max_loop_rounds`.
6. No legacy hard-fail fields remain.
