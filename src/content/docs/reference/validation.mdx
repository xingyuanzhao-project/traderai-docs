Every workflow is checked before it can run. The check happens automatically when
you save in the app, and you can also run it yourself.

## What the check enforces

**Structure**

- Every `node_id` is unique, and every connection endpoint exists.
- `node_type` is one of `agent`, `agent_group`, or `tool`; `edge_type` is one of
  `data_flow`, `tool_call`, or `synchronization`.
- `agent_group` nodes carry `group_config`.

**Connections**

- `data_flow` consumers are `agent` or `agent_group` (tools receive input only
  through calls).
- Tools are authorized only through `tool_call` edges; agents with tool access keep
  `config.tools: []`.

**Loops**

- A node with `agent_loop_default: false` that loops must have a self-loop
  `data_flow` connection carrying `loop_rounds`.
- `loop_rounds` is at most `config.max_loop_rounds`.
- Loops must have a single way in.

**Success rules**

- Every requirement's `tool_names` is reachable, either directly through a
  `tool_call` edge, or indirectly over `data_flow` with `expose_downstream_state`
  upstream and `read_upstream_state` downstream.

<Aside type="caution">
Three legacy fields now fail the check: `NodeConfig.termination_conditions`, `completion_contract.criteria`, and `completion_contract.missing_input_policy`. Remove them from any old workflow before running.
</Aside>

## Check it yourself

There are two levels.

**Level 1, structure (offline, free, instant).** Confirm the workflow is
well-formed without calling any model or data source. Saving in the app runs
exactly these checks and refuses an invalid workflow, telling you why.

**Level 2, live end to end (costs tokens and calls data sources).** Run the
workflow with real provider keys and confirm each node reaches `completed` with the
required evidence. Save this for workflows you are about to publish or run on a
schedule.

<Aside type="note">
Every bundled [example](/guides/patterns/) passes Level 1. Check your own workflow at Level 1 while you build, and at Level 2 before you rely on it.
</Aside>

## Before you publish

1. It passes Level 1 with no errors.
2. Every agent has `mode: explicit` with at least one evidence-backed requirement
   (planners and critics may use `evidence: null`).
3. Every `tool_names` entry in a rule is reachable from that node.
4. Labels are tight roles; procedures live in `instruction`.
5. Loop budgets (`loop_rounds`, `max_iterations`) are set deliberately, within
   `max_loop_rounds`.
6. No legacy failing fields remain.
